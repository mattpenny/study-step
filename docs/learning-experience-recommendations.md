# 讓學生「學得容易」的建議

目標不是加更多題目，而是減少學生卡住的地方。小學生覺得難，通常不是數學本身難，而是三件事：

1. **不知道該練哪個** —— 面對 768 個知識點無從入手
2. **錯了不知道為甚麼錯** —— 只知道「答錯，正確答案是 5」
3. **一節太長** —— 要做 40 題才叫完成，中途就放棄

以下按「用了現有資產沒有」和「成本」排序。**前三項都不需要等題庫做完**，用現有的 156 道
小一題目就能運作。

---

## 第一優先：用已經有的東西

### 1. 錯誤類型診斷（最高回報）

我們寫題目時，干擾項本來就是「常見錯法」。但資料裡沒有記錄**是哪一種錯法**：

```jsonc
// 現在
{ "key": "A", "text": "3 個" }
// 應該
{ "key": "A", "text": "3 個", "misconception": "用 5−2 數區間，漏掉起點" }
```

學生選 A，介面就可以說「你用了 5−2 = 3，但 2 到 5 要把起點 2 也算進去」，而不是
「答錯，正確答案是 4 個」。

**為甚麼這是最高回報**：它把「分數」變成「診斷」。學生不用自己猜錯在哪，老師也一眼看到
全班同一個誤解。現有 18,515 個選項，**0 個有標記**——這是純資料工作，不改架構。

成本：schema 加一個欄位、介面加一行；新寫的題目順手標（我寫小一時其實已經知道每個干擾項
代表甚麼錯法）。

### 2. 「今天學甚麼」入口（先修優先）

不要讓學生自己挑知識點。用 2,812 條先修邊問三條問題（年級、想學的單元、自評），
直接給「今天先補這個」。

理由：學生練錯東西是最貴的浪費。想學「配方法」但「完全平方公式」沒學好，練一百題
都學不會——而這個關係我們已經有了。

成本：一個開始畫面 + 呼叫現有引擎。`diagnose/?grade=P4` 與 `?target=` 已經支援。

### 3. 十分鐘一節，有明確終點

一節 8–10 題，結束時說「你今天學會了甚麼」。不是「做完 40 題」。

引擎已經支援 `limit`，這主要是介面與節奏設計。同時允許中途離開、下次接續。

---

## 第二優先：香港小學特別需要的

### 4. 線段圖（bar model）與數線

香港小學的應用題大量用線段圖。我們現在有 SVG 圖示支援，應該做**可重用的線段圖與數線元件**，
而不是每題手畫。這對「應用題看不懂」的幫助，比多寫 50 題更大。

### 5. 中英對照數學詞彙

不少香港學校是英語授課，學生要同時知道「分子 = numerator」。在每個知識點顯示中英對照，
是低成本、高實用的一項。i18n 層已經有，這只是內容。

### 6. 讀題輔助

小學應用題真正的門檻是**讀題**，不是計算。兩件事很便宜：

- 把題幹裡的數字和單位標示出來（粗體或底色）
- 加「朗讀」按鈕（瀏覽器內建語音，零成本）

### 7. 錯題三天後再出

答錯的題目排進 3 天、1 週後的重溫。成本低，對記憶的效果比一次做對更好。

---

## 第三優先：動機與可見度

### 8. 掌握地圖

「小一 38 個知識點，你已掌握 12 個」，配現有的知識圖譜顯示。給學生方向感，而不是一個數字。

### 9. 家長摘要

按 (d) 的決定，家長只看總分與薄弱點摘要，不看逐題答案。

---

## 不建議做的

- **計時、排行榜、扣分**：對已經落後的學生只會增加焦慮，令他們更不想打開。
- **小一至小三要求打字**：輸入本身就是障礙。應該以點選為主，數值題用大按鈕數字鍵盤。
- **一次顯示全部解析**：現在的做法（答完才顯示）是對的，不要為了「方便」提前給答案。

---

## 如果只做三件事

1. **錯誤類型診斷**（把分數變成診斷）
2. **「今天學甚麼」入口**（不要讓學生自己找）
3. **十分鐘一節**（讓學生願意再來一次）

這三項都不需要新題目、不需要後端，而且直接對著上面三個「卡住」的原因。
