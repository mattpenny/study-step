# 商業化之前必須先處理的三件事

## 一、授權：目前不能收費

`LICENSE` 是 **CC BY-NC 4.0（Attribution-NonCommercial）**，繼承自上游
`xiaoyang111222/cn-math-taxonomy`。NC 的意思是「不得主要為商業利益或金錢報酬而使用」。

這不是灰色地帶：**用這份資料開收費產品，直接違反授權。**

### 三條出路

| 做法 | 成本 | 評價 |
| --- | --- | --- |
| 向上游作者取得商業授權（雙重授權） | 一封信 | 最便宜，先做這個。作者持有版權，可以另外授權給你 |
| 重寫成非衍生作品 | 等於你本來就要做的題庫工程 | 可行，見下節 |
| 維持非商業，改為賣服務 | 低 | 邊界模糊：用 NC 作品提供收費服務，仍然有風險 |

### 你的路線圖剛好也是授權問題的解法

目前這份資料裡，哪些是上游的、哪些是你的：

| 內容 | 來源 | 授權影響 |
| --- | --- | --- |
| 768 個知識點的名稱、描述、掌握標準 | 上游 | NC 綁住 |
| 2,812 條先修邊 | 上游 | NC 綁住 |
| 7,187 道題（大部分） | 上游 AI 初稿 | NC 綁住，而且品質不能賣 |
| **EDB 學習階段／範疇／單元的對照** | 你做的 | 你的 |
| **609 條學習重點的抽取** | 你做的 | 你的 |
| **212 道重寫題目** | 你寫的 | 你的 |
| 全部程式碼、介面、i18n | 你做的 | 你的 |

所以：**每重寫一個單元，對上游資料的依賴就少一分。** 當知識點改為由 EDB 學習重點
重新推導（而不是沿用上游的清單）、題目全部自己寫，整份資料就不再是上游的衍生作品，
可以改用你選的授權（包括商業授權）。

這件事你本來就要做（22,805 題），只是它同時是法律上的解法——這一點值得記住。

# 可以怎麼收費（順序由易到難）

## 1. 學校訂閱（最現實）

按學生人數或全校授權。學校有預算（IT in Education、QEF），而且「節省老師批改與
診斷時間」是可量化的價值。

需要的東西：老師儀表板、班級管理、SSO、中英雙語、教科書對照、PDPO 文件。

## 2. 補習社 / 學習中心（最快成交）

他們人數少、決策快、對「診斷報告」有直接需求。單價低但銷售周期短，適合先跑通。

## 3. 家長訂閱（最難）

參考價：KooBits 香港約 **HK$987/年/學生**。B2C 要花營銷費，而且要和一堆成熟產品競爭。
除非有明顯差異（例如 EDB 對齊 + 先修診斷），否則不建議先做。

## 4. 免費增值

練習免費、診斷報告與家長摘要收費。轉換率通常 2–5%，需要很大流量。

# 建議的次序

1. **先寄一封信給上游作者**，問商業授權。成本一封信，答案決定後面所有事。
2. **清掉 pansgo 的連結與統計端點**（半天）。
3. **選一個切入點**：香港小學數學、面向學校、老師儀表板。不要一開始做家長 B2C。
4. **找 3–5 間學校做試點**，免費用一學期，換取真實使用數據與推薦。沒有試點數據，
   定價只能靠猜。
5. **有了試點再定價**，按「節省老師時間」定，不要按題目數量定。
6. **最後才建後端**（帳戶、班級、作答紀錄）。在沒有學校承諾之前，後端是純成本。

## 要算進去的成本

- **內容**：22,805 題，這是最大的一筆。AI 生成 + 老師審，不是純人力也不是純機器。
- **LLM API**：老師上傳筆記 → 生成 10 題，每次呼叫都要錢。
- **後端與儲存**：學生作答紀錄會一直長。
- **支援**：老師會打電話來。
- **銷售周期**：香港學校由接觸到簽約，通常要一個學年以上。

## 一句話

**不要賣「知識圖譜」或「題庫」——那是資料，而且目前不是你的。
要賣「幫老師省下批改與診斷時間、幫學生找到該補的那一步」——那是服務。**
