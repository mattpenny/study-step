# 怎樣把題目擴展到覆蓋整個 EDB 課程

做過 S11 之後，答案比一開始清楚很多。核心結論：

> **不要「按知識點」擴展，要「按學習重點」擴展，並讓每個單元的覆蓋率可以驗證。**
> 知識點仍然是出題的單位（引擎按知識點出題），但**學習重點是驗收的單位**。

原因見下面第一節——S11 一開始有 26 個知識點，對完學習重點只剩 14 個，另外 12 個根本不屬於
這個單元。如果按知識點埋頭寫，那 12 個點的題目會全部寫錯位置。

---

## 一、先把「學習重點清單」做出來（已完成）

`python3 scripts/extract_edb_objectives.py` → `docs/hk-edb/objectives.json`

| | |
|---|---:|
| 學習單元 | 164 |
| 學習重點 | **609 條** |
| 數學知識點 | 768 |
| 平均每條學習重點對應 | 1.26 個知識點 |

小學用 `1. 2. 3.` 連續編號、初中高中用 `11.1 / 12.3` 這類編號，兩套版式分開解析。

**已知限制**：學習重點本身含數字時會被截斷（例如 1N1「認識 1 至 20 的數」只抽到「認識」），
3M5 重量抽不到。所以清單用來**定位和數覆蓋**，逐個單元動手前仍要掃一眼原文——S11 就是這樣
發現 12 個知識點放錯單元的。

## 二、每個單元先歸屬，再出題

`docs/hk-edb/unit-overrides.json` 記錄逐點修正。S11 的教訓：人教版「第十七章 因式分解」
「第十八章 分式」整章對到 S11，但 EDB 把平方差／完全平方放在 S12（12.2/12.3）、
代數分式放在 S13（13.1）。按章對照會系統性地多算。

**做法**：每個單元動手前，把該單元的知識點逐個對到學習重點編號，寫進題目檔的 `objectives`：

```jsonc
"objectives": [
  { "code": "11.1", "text": "理解多項式的概念", "topics": ["cnm_031", "cnm_032", "cnm_033"] },
  { "code": "11.2", "text": "進行多項式的加、減、乘及其混合運算", "topics": [ … 8 個 … ] },
  { "code": "11.3", "text": "因式分解多項式", "topics": ["cnm_150", "cnm_151", "cnm_155"] }
]
```

`merge_hk_questions.py` 會驗證：

- 每個知識點**必須**歸到某一條學習重點（沒有歸屬 = 這題不服務任何課綱條文，要嘛搬單元、要嘛刪）
- 每條學習重點**必須**有題目
- 同一知識點不能同時掛在兩條

這就是「覆蓋率可驗證」：不看感覺，看報告。

```
S11    多項式        14 點  56 題
         11.1   理解多項式的概念                     12 題
         11.2   進行多項式的加、減、乘及其混合運算            32 題
         11.3   因式分解多項式                      12 題
```

## 三、用模板吃掉能模板化的四成

知識點的 `type` 欄位已經標好性質：

| 類型 | 知識點 | 佔比 | 建議做法 |
|---|---:|---:|---|
| procedural | 310 | 40% | **參數化模板**：固定題幹結構，隨機生成數字，`verify` 自動核對 |
| conceptual | 222 | 29% | 人手寫（概念辨析、判斷題） |
| reasoning | 121 | 16% | 人手寫（證明、推理） |
| application | 81 | 11% | 人手寫（應用題，要香港情境） |
| modeling | 34 | 4% | 人手寫 |

小一 procedural 佔 61%，中四至中六 44%，中一至中三只有 32%。**所以小學最適合先做**，
一來可模板化的比例最高，二來 P1–P6 的單元編號直接帶年級（4N3 = 小四），不像 S1–S3
EDB 不指定年級。

模板長這樣（同一個模板換參數就是十幾道題，每道都獨立驗算）：

```jsonc
{ "template": "add_fractions_same_denom", "params": { "a": [1,5], "b": [1,5], "den": [4,12] },
  "prompt": "計算 {a}/{den} + {b}/{den}。", "answer": "{a+b}/{den}", "verify": "({a}+{b})/{den}" }
```

## 四、批次節奏

1. **每批 5 個單元**，寫完 → `merge --check` → 看覆蓋報告 → 給你看一眼再繼續。
   一次寫 115 個單元，風格錯了要全部返工。
2. **順序：小學 → 中一至中三 → 中四至中六**。小學可模板化比例最高、年級明確、題目短、
   驗算最可靠；高中（尤其 M1/M2 微積分）最需要人手判斷。
3. **每個知識點 4 題**（basic 2 / standard 1 / advanced 1）。引擎對每個知識點最多問 2 次，
   4 題才夠在答錯時換一道同級或更易的。

## 五、規模估算

| 做法 | 題目數 | 說明 |
|---|---:|---|
| 每知識點 2 題（最低） | 1,536 | 引擎能跑，但答錯時未必有第二題可換 |
| **每知識點 4 題（建議）** | **3,072** | 與現狀密度相同 |
| S11 實際密度 | 19 題/學習重點 | 因為 14 個知識點只對 3 條學習重點，偏密；其餘單元不必這麼多 |

按 40% 模板化估算：約 1,230 題可由模板產生（仍需人手設計模板與驗算規則），
其餘約 1,840 題逐題寫。

## 六、還沒解決的三件事

1. **術語**：11 個知識點仍是內地叫法（勾股定理 6、整式 4、銳角三角函數 1），
   單元名卻是畢氏定理／多項式／三角比。出題時我一律用香港叫法，但**知識點名稱本身還沒改**。
2. **沒人審**：題目只做到「算術上正確」，教學上合不合適、選項夠不夠迷惑、用字深淺對不對，
   都沒有老師看過。上游那批題的教訓是：不寫明，使用者就會以為審過。
3. **S1–S3 的年級**：EDB 不指定哪個單元在哪一年教。要按「班」出題，需要你提供學校的
   教學進度表。

## 七、下一步（建議）

按這個順序做，回報最高：

1. **S12 恆等式 + S13 公式** —— 剛讀完這兩單元的原文，接著做最省事，而且能順手驗證
   S11/S12/S13 的分割對不對。
2. **小一至小六**（222 點）—— 模板化比例最高，一輪就能把整個小學階段做完。
3. 再做中一至中三、中四至中六。

每批完成後 `validate.py` 與覆蓋報告都會更新，你可以在 <https://mattpenny.github.io/study-step/>
直接試。
